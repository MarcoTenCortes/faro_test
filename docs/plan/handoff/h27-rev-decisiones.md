## D1 (G1, matizado → SE APLICA) · El re-PING de después de inyectar tiene que ARRANCAR

Hecho reproducido: el PING de antes de `boot()` contesta `{ok:true, booted:false}` aunque el arranque vaya a fallar (sólo carga una hoja), así que un script recién inyectado cuyo arranque falla pasa los dos PING de `asegurarAhora`: REQUEST_HOST_PERMISSION da `{ok:true}`, el panel apunta «Content script inyectado» y dice «Listo». Es el «Listo» falso que H27 vino a quitar, y ninguna prueba lo caza.

- **R1**: en `case MSG.PING:` de bootstrap.js, ANTES de contestar: `if (msg.arrancar && !arrancado && !bootError) await boot().catch(() => null)` (la guarda `!bootError` evita gastar el segundo intento y otro `console.error` en un script ya roto). Un PING con `arrancar` que sale `ok:true` implica `booted:true`; roto → `{ok:false, alive:true, booted:false, error}`. El pin de bootstrap-wiring «PING y SETTINGS se contestan antes de boot() y no lo arrancan» pasa a: sólo el PING con `arrancar` lo arranca, con la línea literal dentro de `case MSG.PING:` y el `eq(lineas(entre('case MSG.PING:', 'case MSG.SETTINGS: {')), […])` con esa línea en segunda posición.
- **R2**: `asegurarAhora` manda `{ type: MSG.PING, arrancar: true }` en `antes` y en `despues`; `contentStatus` y `watchStalledStep` siguen con el PING ligero (lo que ganó H11). Reescribir el comentario de las l.~493-494 y el JSDoc de `ensureContentScript` (~447-453): tras inyectar, el PING pide arrancar porque un PING ligero sólo prueba que hay un oyente. Prueba con el rig: `contentReply` que contesta `{ok:true, booted:false}` a un PING sin `arrancar` y `{ok:false, alive:true, error:'x'}` a uno con `arrancar` → REQUEST_HOST_PERMISSION da `{ok:false, kind:'roto', error:'x'}` y la secuencia pinada sigue `['faro:ping', 'faro:ping', 'faro:settings']` sólo cuando el segundo es bueno (revisar el `eq` de la l.~797: los dos PING llevan `arrancar: true`).
- **R4**: PINES:191 (`const despues = await sendToTab(tabId, { type: MSG.PING })` → `{ type: MSG.PING, arrancar: true }`, y `antes`), PINES (bootstrap-wiring), h27-contrato.md §1.1 (la excepción, con este motivo), PLAN3 §3.1 (idem, una frase), FLUJOS §4.3 («exige el segundo PING bueno» → «el segundo PING pide arrancar»), REFERENCIA §6 «Estado del content script» (el PING con `arrancar`), README («Content script roto dice qué módulo no cargó» vale desde el primer PING con `arrancar`).

## D7 (G7, matizado → SE APLICA) · Lo del manifest se comparaba por cadena exacta contra `host_permissions`
