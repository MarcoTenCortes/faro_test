# Faro — contexto para trabajar en este repo

Este fichero es el mapa completo del proyecto para una sesión nueva: qué es, cómo
está montado, cómo fluye cada cosa, qué contratos hay entre piezas, qué
decisiones no se negocian y cómo se comprueba. Léelo entero antes de tocar
código; con esto no hace falta explorar el árbol para orientarse. El README
cuenta lo mismo para personas, con más prosa; `docs/INSTALL.md` es la guía de
instalación y problemas frecuentes. Mantén los tres al día cuando cambies algo.

## 1. Qué es

Extensión de Chrome MV3 («Faro») que convierte un **opencode local** (servidor
headless HTTP+SSE en `127.0.0.1:4096`) en un copiloto dentro de Jira y
Confluence. Chat en panel lateral; el modelo consulta Atlassian a través del
servidor MCP `mcp-atlassian` (sólo lectura) configurado en opencode; la
extensión además **lleva al usuario hasta la respuesta** (despliega el árbol de
páginas de la izquierda y navega una vez) y **subraya en la página** el
fragmento del que habla (Custom Highlight API + overlay en Shadow DOM).

Cinco piezas: la página (Jira/Confluence) · la extensión · opencode · el LLM
(el que tenga opencode; Faro no habla con ninguna nube) · el MCP de Atlassian.

- Sin build, sin dependencias npm: módulos ES que Chrome carga tal cual. Node ≥18.
- Todo en español: comentarios, UI, logs, nombres de test, muchos identificadores
  locales. Nombres exportados en inglés.
- Verificado contra **opencode 1.2.25**. Chrome ≥116. El usuario real usa un
  Confluence Data Center propio (`confluence.simplprogramme.eu`, fuera de
  `*.atlassian.net`) y modelos vía `github-copilot/*` y `opencode/*-free`.

## 2. Arrancar y comprobar

```bash
npm run check              # sintaxis (node --check) + orden (TDZ) + manifest + 540 pruebas unitarias
npm run test:integration   # arranca su propio opencode serve (puerto 4123) y ejercita el cliente real
npm run harness            # Confluence de mentira en http://127.0.0.1:5175 (también .claude/launch.json → preview_start "harness")
```

- Extensión: `chrome://extensions` → modo desarrollador → cargar `.` (id fijo
  `ickohiffpicdfeameogbihbcanbjibmk`, derivado de `key` del manifest). Tras
  cambiar código hay que recargar la extensión y la pestaña.
- opencode: `opencode serve --port 4096 --cors chrome-extension://ickohiffpicdfeameogbihbcanbjibmk --print-logs --log-level INFO`
  con `OPENCODE_SERVER_PASSWORD` (la misma en Ajustes del panel).
- Banco visual: `http://127.0.0.1:5175/` (botón **Autocomprobación completa** o
  `await faroHarness.actions.selfcheck()`), `http://127.0.0.1:5175/harness/panel-preview.html`
  (el panel real con una conversación de ejemplo). Ejecutar la autocomprobación
  **con el Browser pane visible, a 1280×900**: oculto, Chrome estrangula los
  temporizadores y se atasca en la 6-7. Flaky por entorno: «el arbol lateral se
  desplaza solo» (viewport bajo) y «el barrido no se queda aparcado» (timing).
- Windows: el Bash tool trunca comandos >8 KB y mangla `\` en heredocs: JS con
  Write/Edit, nunca con heredoc. PowerShell 5.1 no tiene `&&`.

## 4. Flujos, paso a paso

### 4.1 Arranque del panel (`panel.js`)
`init()` → `getSettings` → `wireEvents` → `refreshTab()` (pestaña activa: olvida marcas si cambió de página **antes** de reasignar `state.tabId`; `parseAtlassianUrl`; hosts conocidos por `getSite`; `changedHost` → `bootForSite()`).
`bootForSite()`: `buildClient()` → `health()` (si falla: pantalla connect con el comando de arranque) → `connect()` (SSE) → skill guardada → `models()` → `listMcp()` + `config()` (GET /config: la configuración entera, con los `environment` de los MCP y sus claves en claro; sólo se miran los hosts, nunca se guarda ni se registra) → `saved = getSite(host)` → `found = mcpForHost(config, host, {status: mcp})` (el MCP que lleve este dominio en JIRA_URL o CONFLUENCE_URL, sin los `enabled: false`; CONECTADO antes que nada, después el de los dos productos, en igualdad el primero) → si está conectado y (no es el apuntado, o el apuntado no está `configured`, o trae un host enlazado nuevo): `siteRecords({…, mcpName: found.name, jiraHost, confluenceHost})` → `saveSite` de cada host (el otro queda enlazado) → «MCP reconocido»; si lleva el dominio pero no está conectado, «MCP sin conectar» y NO se apunta (apuntar uno caído pisaba el recién verificado y el panel entraba en bucle en la pantalla de claves: lo encontró la revisión) → `mcpStatusFor(mcp, host, chosenMcpName(config, saved, host, {status: mcp}))` (opencode → lo apuntado → el nombre por host) → la pantalla de claves dice QUÉ bloque está caído («El MCP «nombre» está registrado pero en «failed»…») → `state.mcpConnected`, `state.sources = normalizeSources(saved.analysisSources)`, `paintSourcesUi()` (ANTES de cualquier pantalla; `refreshTab` los vacía al cambiar de host) → (si el MCP del host no está y no se saltó: pantalla setup con un bloque por producto → `saveKeys` → `configureMcp({host, jira, confluence, dataCenter})` → `buildMcpConfig` → enseña el bloque para `opencode.json` → `waitForMcpReady` tras reiniciar opencode → `finishSetup`: `verifyCredentials({product})` por cada producto habilitado → `siteRecords` → `saveSite` de cada host, «Sitio enlazado») → contexto/memoria/índice del host + `state.linkedContext = loadLinkedContext(saved)` (sólo en Jira con `saved.confluenceHost`: el CONTEXT.md de ese host) → `restoreConversation()` (lista mensajes de la sesión guardada; los del asistente se agrupan por turno y pasan por `splitAnchorsBlock`; al final, tarjeta viva del análisis si sus marcas siguen en la página, o tarjeta atenuada «Volver a marcar» del último análisis con anclas).

### 4.2 Un turno de chat (`send()`)
1. Guardas; `pick` pendiente se consume (acompaña sólo a ESTA pregunta); se capturan `skill`, `sources` (sólo en Análisis y si `hasSources`), `pageIdAlPedir` (`site.pageId` o `currentPageId(index, tabUrl)`) y `tituloAlPedir`: `state.site` cambia con la pestaña y lo de después habla del turno que se mandó; testigo de turno + `AbortController` propio; `setStreaming(true)` (bloquea enviar y el desplegable de skill).
2. Si `skill === 'analisis'`: `readPageDigest()` → `MSG.PAGE_DIGEST` al content script → `{text, blocks:[{id,tag,text}], count, chars, truncated, url}` o `{ok:false, reason:'editando'|'sin-texto'}`. Se declara bajo la pregunta («con el texto de la página (N bloques)» · `sourcesNote(sources)`).
3. Sesión de opencode por host (`createSession` con `SAFE_PERMISSIONS`: deniega bash/read/write/edit/patch/glob/grep/list/webfetch/task).
4. `client.runTurn(sessionID, {text: selectionBlock(pick)+pregunta, files (imagen señalada), model, system: baseSystem({site, contextMd, memoryMd, page, skill, digest, linkedContext, sources})}, {signal, stallMs 90000, onUpdate: paintTurn})`. `runTurn` abre el stream, manda `prompt_async`, reconstruye el turno con `TurnTracker`, vigila (90 s sin contenido → `stalled`; 15 min máx), rechaza `question.asked`/`permission.asked` automáticamente, devuelve `{ok, parts, text, tools, model, rawError, structured}`.
5. Al terminar: `splitAnchorsBlock(turn.text)` → `answer` (prosa) + `anchors`; `paintTurn(final)`; `warnAboutSources(turn.parts, bubble, {sources, pageId, title})` (sin MCP → «Páginas base sin leer»; exclusivo → `consultedOutside` → «Fuera del alcance», ambos con `noticeNode`); `saveSite({model})`; `growIndex(turn.parts)` (harvestIndex de salidas de herramientas); `growTreeFromPage()` (`MSG.TREE_SNAPSHOT`, `mergeIndexKeepingTree`); `offerNavigation(answer, bubble, skill)`; `offerNotes(answer, bubble, {skill, anchors, digest, digestReason, urlAlPedir, signal, conBase})`.
6. `finally`: sólo el turno cuyo testigo sigue vigente apaga `setStreaming`. El botón Parar aborta el controlador y la sesión; cancelar durante la lectura de la página devuelve la pregunta al cuadro.

`paintTurn` pinta filas de herramientas (título del MCP o `prettyTool`), colapsa a «N consultas a Atlassian» al final, esconde una valla ```json abierta que ya empieza como el bloque de anclas («Situando las observaciones…») y renderiza la prosa con `renderMarkdown(prose, {onLink: openUrl, onNote: focusNote})`.

### 4.3 Navegación (General/Búsqueda)
`offerNavigation` → sin índice: `sinMapaCard`; `planNavigation(client, {…, here, force: skill.alwaysPlan, navMode, learnAncestry, onIndex})`:
- Búsqueda: el modelo cierra con «Destino: título (id N)» (Confluence) o «Destino: CLAVE-123» (Jira) → `declaredDestination` (sólo última línea, no citada ni en código; la página o la incidencia abierta → `none` «ya estás») → sin turno extra. General: `shouldPlan` (heurística barata) y, si apunta a algo, `promptStructured` con `NAVIGATION_PLAN_SCHEMA` en sesión desechable «Faro · planificador». `excludeId = site.pageId || site.issueKey || currentPageId(index, here)`.
- `learnAncestry(destination)` → `MSG.PAGE_ANCESTORS` al content script → `fetchAncestors` (GET mismo origen, id numérico validado) → cadena de padres fundida en el índice (caché por sesión `state.ancestryFetched`). Sólo para `confluence-page`.
- `validatePlan(raw, {index, origin, host, here})`: destino sólo si está en el índice y es del mismo origen; los pasos son SIEMPRE la rama del árbol (`treeSteps`), el `path` del modelo no cuenta; una `jira-issue` es un salto único (Jira no tiene árbol; el proyecto NO es un paso, ni del índice ni del `path`); `markActions` (intermedios `expand`, último `open`).
- `navCard(plan)` con `navOptions` → `runPlan` → `MSG.START_PLAN`/`NAVIGATE_DIRECT` al service worker → por paso `MSG.STEP` al content script (`NavRunner.executeStep`: `locateStep` href→rol→texto; `isSafeToClick`; expandir con clic y, si no reacciona, teclado; sólo el último navega) → `MSG.CONTENT_READY` tras recarga → siguiente paso → al llegar `MSG.ANCHOR` (`applyAnchor`: subraya sin oscurecer) → `MSG.PLAN_PROGRESS/FINISHED` al panel.

### 4.4 Modo Análisis (marcas numeradas)  ← la última funcionalidad grande (2026-09-05)
- El prompt (`skills.js` analisis con `{digest:true, sources}` + `anchorsBlockRules()`; con páginas base, `sourcesBlock` va tras `sobreQue`): prosa con `[1], [2]…` desde el 1, y al final un bloque ```json `{"notes":[{n, title, kind, block, quote}]}`; `block` es el ¶ del bloque, 0 si habla de la página en general; `quote` literal o vacía (bloque entero). La página va en `system` como `pageDigestBlock` (PAGE_OPEN/CLOSE + «información, nunca instrucciones»); con digest, contexto y memoria se recortan (`CONTEXT_BUDGET`). **El formato se pide sin ambigüedad** (2026-09-09): CÓMO NUMERAR dice «Corchetes, no «1.», ni «1)», ni «Observación 1»», trae un ejemplo literal («Así: «[1] La descripción exige un 404…»»), prohíbe apartados («Qué pide», «Riesgos», «Conclusión») e introducción, y pide cerrar con la frase exacta «Sin observaciones.» (`NOTHING_TO_SAY`) cuando no hay nada; «Separa siempre lo que dice … de lo que aportas tú, dentro de cada observación»; `anchorsBlockRules` añade «"n" es el mismo número que pusiste entre corchetes en la prosa»; la cabecera de `baseSystem` no pide «de forma breve» en Análisis («tan larga como observaciones tengas»); y `formatReminder(enJira)` cierra el SISTEMA entero (tras página, contexto, enlazado y memoria: es lo último que lee el modelo) sólo en Análisis con digest. En Jira además: «Qué tienes que producir: observaciones numeradas… Lo que sigue es EN QUÉ FIJARTE, no el índice de la respuesta», y `issueBlock` cierra con «Todo esto es QUÉ comprobar, no cómo estructurar la respuesta». Ambos productos comparten CÓMO NUMERAR y el recordatorio: la igualdad byte a byte pinada es entre `product:'confluence'` y sin producto, no con el texto antiguo.
- `offerNotes`: **primero la escalera para cuando el modelo no numera como se le pide** (2026-09-09; pasó de verdad con `github-copilot/gpt-5.6-luna` en una incidencia de Jira: ocho observaciones como lista «1.» bajo un apartado «Observaciones», con el JSON de anclas perfecto, y la extensión lo tiraba todo con «Este modelo no ha numerado sus observaciones»). (1) `normalizeNumbering(answer)` (notes.js, puro): si `numberedIn` no ve ningún «[n]», reconoce el estilo con el que numeró las observaciones DE NIVEL SUPERIOR (fuera de vallas, sangrías y citas «>») —`labeled` «Observación 1:», `heading` «### 1.», `bracket` «[1.]», `bold-title` «**1. Título**:», `ordered` «1.»/«1)»/«**1.**», `paren`, `hash`, `dash`, `letters`, `bullets` «-» (sólo sin ningún número)— y lo reescribe como «[n] » (conservando negritas y «###», separando ítems con línea en blanco) SOLO si la secuencia es exactamente 1..N (N ≤ `NOTE_LIMITS.max`; los estilos débiles exigen N ≥ 2); antes, `unwrapWholeFence` (la respuesta entera dentro de ```markdown/```/```text). Falso positivo asumido y documentado: unos pasos «1. Abre… 2. Pulsa…» de nivel superior SON observaciones. Con `style` ≠ `brackets` se repinta la burbuja (`repaint(prose)` de `send()`) y se apunta «Numeración adaptada». (2) `observationNumbers(answer, anchors)`: los números de la prosa y, si no hay, los del JSON si empiezan en 1 («Numeración del JSON»). `analisisNuevo = numeros[0] === 1`; con marcas previas es seguimiento sólo si hay números, o `saysNothingToSay`, o `looksLikeFollowUp(question, answer)` (la pregunta cita un punto, la respuesta es corta o cierra con «Sin observaciones.»); si no, es un análisis nuevo sin numerar. `NOTHING_TO_SAY` «Sin observaciones.» como última línea → «Sin observaciones» + aviso neutro. Sin números: respuesta < `NOTE_LIMITS.shortAnswer` (400) o una herramienta en `error` → «Sin marcas» + aviso con `withRetryNumbered` (botón «Pedirlo numerado»: `numberedReminder(question)` al cuadro y `send()`); si no, sigue. Sin permiso → `showPermissionNotice()`. ## 6. Contratos de datos
- **Ancla** (`validateAnchor`): `{kind:'heading', headingText}` · `{kind:'text-quote', exact(3..300), prefix, suffix(≤80)}` · `{kind:'block-quote', block(1..9999), hint(≤80, obligatoria), exact('' | 3..300)}`. `ANCHOR_LIMITS.affixMax === DIGEST_LIMITS.hintMax` (pinado).
- **Nota** al content script: `{n, title, kind('dato'|'supuesto'|'hueco'|'contradiccion'|'riesgo'|''), anchor}`; claves exactas pinadas por test SEGURIDAD. Máx 12.
- **Digest** (`MSG.PAGE_DIGEST`): bloques = elementos de bloque (BLOCK_TAGS/BLOCK_ROLES) con texto PROPIO (`buildTextIndex(el,{boundary})`, frontera = bloques anidados y, en una incidencia de Jira, la interfaz), ocultos fuera (`aria-hidden`, sin client rects salvo `display:contents`), 1-based, topes 30000 chars / 400 bloques / 1500 por bloque, `truncated`. Etiquetas: h1-h6, p, li, celda, cita, código, pie, def, txt. **Ámbito** (`digestScope()`): `{roots:[{el, tag?}], chrome}`; en una incidencia, `roots` son título + módulos y `chrome` la interfaz; en Confluence, `[{el: contentRoot()}]` y `''`.
- **Plan**: `{navigate, mode:'direct'|'assisted', destination:{kind, id, title, url, path}, anchor, steps:[{kind,id,title,url,path,label,action:'expand'|'open'}], explanation}`. `TARGET_KINDS`: confluence-page, confluence-space, jira-issue, jira-project.
- **Índice**: sólo rutas relativas (`toSafePath`); `resolveTarget(index, origin, {kind,id})` reconstruye la URL contra el origen de la pestaña; `ancestryOf` da la cadena de padres.
- **Pick**: texto `{kind:'text', text(≤4000), prefix, suffix, heading, pageTitle, url}` · imagen `{kind:'image', alt, imageTitle, caption, filename, around, image:{url,mime,filename}|null}`.
- **Sitio** (`parseAtlassianUrl`): `{host, origin, product:'confluence'|'jira', cloud, spaceKey?, pageId?, projectKey?, issueKey?, wikiPrefix?}`. `pageId` sólo si es numérico (también en `?pageId=`).
- **Sitio guardado** (`sites[host]`, `saveSite`): `{host, configured, mcpName, product, cloud, jiraHost?, confluenceHost?, skippedKeys?, onboarded?, indexedAt?, model?, skill?, wikiPrefix?, analysisSources?}`. `mcpName` es el del host desde el que se configuró (un host enlazado apunta al de su pareja); `jiraHost`/`confluenceHost` sólo si es OTRO host (`siteRecords`, claves exactas pinadas). `linkedContext` en el estado: `{host, contextMd(''), index(null)}|null` — existe en cuanto hay `confluenceHost` guardado, aunque ese Confluence no esté indexado todavía (`linkedHost()` depende de él); el índice NUNCA se guarda desde Jira.
- **Claves de un producto** (`buildMcpConfig`): `{url, email?, token}|null` por producto; `environment` resultante: `JIRA_URL`+(`JIRA_PERSONAL_TOKEN` | `JIRA_USERNAME`+`JIRA_API_TOKEN`), ídem `CONFLUENCE_*` (Cloud: `CONFLUENCE_URL` = origen+`/wiki`), `READ_ONLY_MODE:'true'`.
- **Páginas base** (`normalizeSources`, en `sites[host].analysisSources`): `{mode:'exclusive'|'open', pages:[{id(/^\d+$/), title(≤200 o «Página N»), path(relativa al sitio o ''), spaceKey|null}]}`; claves de página EXACTAS pinadas; máx `SOURCE_LIMITS.maxPages` (6). `sourcesFromSystem` devuelve `{count, mode}` y `sourcesNote`/`hasSources` aceptan esa forma.
- **Campos de la incidencia** (`normalizeIssueFields`, en `digest.issue`): `{type, status, priority, resolution, assignee, reporter, epic, sprint, fixVersions[], affectsVersions[], components[], labels[]}`, claves EXACTAS (`ISSUE_TEXT_KEYS` + `ISSUE_LIST_KEYS`), valores `clean(…, 120)` con `«»` → `"`, listas ≤ `ISSUE_FIELD_LIMITS.listMax` (10) sin repetir; null si nada vale. `issueProfile` → `{family: 'api'|'bug'|'test'|'epic'|'architecture'|'doc'|'story'|'task'|'', phase: 'cerrada'|'bloqueada'|'en-revision'|'nueva'|'en-curso'|''}`.
- **Confluence enlazado como sitio** (`linkedSite`): `{host, origin:'https://'+host, wikiPrefix, cloud:false}` o null; `sourcesSearchTarget(site, linked)` → `{via:'tab'}` | `{via:'linked', site}` | null.
- **Búsqueda** (`searchPages`): `{ok:true, pages:[{id,title,spaceKey|null,url}], via:'v1'|'v2', ms}` | `{ok:false, reason, status?}`. `SEARCH_LIMITS` `{queryMin 2, queryMax 100, maxTerms 6, defaultLimit 8, maxLimit 20, maxResults 20}`; `SOURCE_LIMITS.queryMin/queryMax/suggestions` los referencian (pinado). CQL: `type=page AND title~"w1" AND title~"w2*"` (comodín sólo en el último término y con ≥2 letras; `"`, `\`, `*`, `?` se quitan).

## 8. Decisiones de diseño (no negociables sin motivo escrito)
1. El panel es el único que habla con opencode; el content script sólo recibe órdenes validadas.
2. El stream SSE vive en el panel (el SW se duerme a los 30 s).
3. El modelo nunca emite URLs ni selectores: identificadores que el panel resuelve contra el índice; validación (`validatePlan`, `validateNotes`, `validateAnchor`) antes de que nada llegue a la página; mismo origen obligatorio.
4. El camino es la rama del árbol leída por la API REST del propio Confluence (`learnAncestry`), no lo que diga el modelo; si no hay camino, se lleva de golpe (nada inventado).
5. Un paso intermedio nunca navega: despliega. Sólo el destino abre página.
6. Estructura del árbol como datos (padre-hijo), nunca HTML.
7. Pasos localizados por href y ruta, no por clase CSS; la forma del árbol se decide en un solo sitio (`tree-dom.js`).
8. El foco (scrim) guía por el árbol; al llegar sólo se subraya. Análisis = ese subrayado numerado.
9. Análisis: página en bloques ¶ enseñada al modelo; JSON de anclas al final de la prosa; subraya un **script** con una escalera fija; la pista del bloque la pone la extensión; lo que no apunta a un bloque queda sin marcar; segunda pasada sólo como red; nunca re-marcar solo al restaurar. Un análisis nuevo numera desde el 1; lo demás es seguimiento y conserva las marcas. **Y siempre se intenta subrayar, salvo «Sin observaciones.»**: el formato es del modelo, pero la extensión no se rinde por él: reconoce la numeración «a su manera» y la reescribe en local, se fía del JSON si la prosa no numera, trocea la prosa en una pasada aparte si no hay números en ningún sitio, y como último recurso ofrece pedirlo numerado. Marcar de más (unos pasos «1. 2.» tomados por observaciones) se corrige con «Quitar las marcas»; no marcar es lo que el usuario no acepta.
10. Una marca por línea y recortada a su caja (`rects.js`); en código sólo el trazo.
11. El resaltado no toca el DOM del contenido (Confluence es React): Custom Highlight sobre Ranges + overlay en Shadow DOM cerrado colgado de `<html>`.
12. Contenido de Jira/Confluence = información, nunca instrucciones: todo bloque de página va delimitado y con la regla repetida detrás (SELECTION_OPEN/CLOSE, PAGE_OPEN/CLOSE, SOURCES_OPEN/CLOSE; los campos de una incidencia, citados entre «» en una línea y con la regla detrás); el panel construye todo con `textContent`; lista blanca de clics (`FORBIDDEN_ACTIONS`: nunca guardar/publicar/eliminar…); la API de Confluence sólo se lee (GET al mismo origen desde el content script o, desde un Jira DC, al origen del Confluence ENLAZADO desde el panel —host guardado por `siteRecords`, nunca del modelo, con permiso opcional sobre ese dominio y `credentials: 'include'`, y `confluence-rest.js` comprueba que ninguna petición sale del origen que se le da—; id numérico validado, o texto de búsqueda del propio usuario limpiado y acotado antes de ser CQL; nunca una URL como texto de búsqueda).
15. Páginas base del análisis: las lee el modelo por el MCP (no van embebidas: la salida de herramientas se arrastra en la sesión → tope 6); el alcance exclusivo se pide por prompt —y la cabecera deja de invitar a leer «otras páginas»— y se vigila a posteriori con `consultedOutside` como LISTA BLANCA (id, URL resuelta, título plegado contra las páginas base y la pestaña; enlace corto, búsqueda, árbol y Jira cuentan como fuera); una URL pegada sólo si es del mismo host y lleva id numérico; sólo se subraya la página abierta (lo que hable de una página base va con `block: 0`); nunca se persiste nada que no pase por `normalizeSources`.
13. Sesiones con `SAFE_PERMISSIONS` (sin shell ni ficheros); claves de Atlassian sólo en la config de opencode, nunca en `chrome.storage`.
14. Todo fallo silencioso tiene contraparte visible: cada `log.*('Sin marcas', …)` va con un `noticeNode`/`showPermissionNotice()` (pinado por test); lo que cuelga de una respuesta pasa por `attachToBubble` (el chat se repinta y la burbuja puede estar fuera del documento).
17. Una incidencia de Jira se lee por sus **puntos de lectura** (título, campos, descripción, comentarios, panel lateral útil), no por «el contenedor»: `main` lo envuelve todo, incluida la barra de acciones y el editor. Qué es contenido y qué es interfaz se decide en UN sitio (`jira-issue.js`, como `tree-dom.js` para el árbol), la interfaz es frontera del texto (ni bloque ni dentro de un bloque), y la escalera de marcado es la misma que en Confluence. Cloud sin verificar: si sus selectores no casan, se lee el contenedor de siempre.
18. Una incidencia se analiza según **lo que es**: el tipo y el estado los lee la extensión de los campos en pantalla (`jiraIssueFields`, en `jira-issue.js`, el único sitio que sabe qué forma tiene una incidencia), no el modelo; la familia y la fase se deducen por nombre (es/en) sólo para ELEGIR qué pedirle (`issueBlock`), y lo que ese tipo y ese estado significan en el proyecto se le remite al CONTEXTO DE ESTE SITIO (que el indexador de Jira ya recoge). Lo que no se reconoce no se inventa: se le pide al modelo que lo deduzca él. Sin campos, que los lea con la herramienta. En Confluence, nada de esto entra.
16. Jira y Confluence son dos productos: **un token cada uno** (en DC son dos instalaciones con PAT propio; el token único de antes sólo valía en Cloud), un solo MCP para los dos, y el otro host **enlazado** al mismo MCP (`siteRecords`) en vez de un segundo proceso con el mismo token. La misma Skill habla distinto según `site.product`: en Jira no hay árbol → Búsqueda con JQL, cierre «Destino: CLAVE», `jira-issue` = un salto único (el proyecto NO es un paso), la tarjeta sólo «Llévame»; la incidencia abierta se excluye como destino. Desde Jira viaja el CONTEXT.md del Confluence enlazado (delimitado, `CONTEXT_BUDGET.linked`, detrás del propio) para saber qué páginas mirar; el índice de Confluence NO (otro origen: `validatePlan` lo rechazaría). En Confluence el prompt es byte a byte el de antes.
19. **Lecturas REST sin tokens** (decidida en `docs/PLAN.md` §5; se implementa en H7-H11): lo que la API del propio sitio da exacto y en milisegundos (una búsqueda JQL, el árbol de un espacio, la muestra de un proyecto, los enlaces de una incidencia, lo que viste y lo tuyo) no se le pide al modelo: el modelo escribe prosa y JQL; la extensión ejecuta, pagina, valida y pinta; si la API no contesta, el camino de siempre sigue entero. Procedencia admitida de cada consulta: la llamada real del MCP (`state.input.jql` de `jira_search`), una plantilla fija con parámetros validados, un filtro del propio sitio, o texto del usuario limpiado. Siempre GET, mismo origen, `maxResults` acotado, campos fijos, tope de tiempo, y por un único `getJson`. Un título del DOM NUNCA se convierte en CQL. En Jira Cloud no hay REST de Jira (410): todo por el MCP.
20. **Actividad y sugerencias** (decidida en `docs/PLAN.md` §5; se implementa en H10-H11): la actividad del usuario es suya y local (ids, claves, títulos y rutas relativas; 30 días; sólo hosts configurados; visible y borrable; nunca en un prompt). Sugerir es gratis y explicado: ninguna sugerencia llama al modelo, cada una dice de dónde sale, Faro nunca añade una página base ni manda una pregunta por su cuenta; ir a una recomendación del host propio pasa por el índice y `validatePlan`.

## 9. Convenciones de código
- Cabecera `/** … */` en cada módulo explicando POR QUÉ existe y el incidente que lo motivó («Pasó de verdad», «Comprobado contra opencode 1.2.25»). Comentarios de razones, no de mecánica.
- Lógica pura separada del DOM/chrome y marcada «Puro/Pura»: es lo que se prueba en Node. Módulos de `src/` no tocan `document`/`window`/`chrome` al importarse (los importan los tests y el banco).
- Lo que viene del modelo pasa por `clean(value, max)` y un `validate*()` que reconstruye un objeto con claves blancas. Límites en objetos `UPPER_SNAKE` (`NOTE_LIMITS`, `ANCHOR_LIMITS`, `DIGEST_LIMITS`, `INDEX_LIMITS`, `NAV_TIMING`, `CONTEXT_BUDGET`).
- Prompts como funciones puras que devuelven `[...].join('\n')`; esquemas como constantes con descripciones en español; secciones en mayúsculas en los prompts de usuario.
- Turnos internos: sesión desechable «Faro · <cosa>» + `promptStructured` + `deleteSession` en `finally`. Todo `chrome.tabs.sendMessage` con `.catch(() => null)`.

## 11. Cómo añadir cosas
- **Módulo puro**: `src/<área>/<nombre>.js` con cabecera de porqué, sin DOM al importar; `test/unit/<nombre>.test.js` con `import { test, eq, assert } from '../harness.js'`. `eq` compara JSON: `undefined` desaparece y el orden de claves importa.
- **Mensaje nuevo**: constante en `MSG` (grupo por dirección), `case` en `bootstrap.js` con import perezoso, `.catch(() => null)` en el panel.
- **Prompt**: función pura en `prompts.js`/`skills.js`/`notes.js`; conservar las frases pinadas o cambiar el test en el mismo cambio; contenido de página siempre delimitado y etiquetado.
- **Comprobación del banco**: dentro de `selfcheck()` (`harness/harness.js`), `// N. …` + `ok(nombre, condición, detalle)`; `runner.clear(); renderPage('page:200'); await wait(320)` antes; devolver la página como estaba; fixtures calculadas desde el DOM (`observacionesPorBloques(pageDigest())`), nunca ordinales fijos. Botón: `<button class="rig-btn" data-act="x">` + `actions.x()`. `window.faroHarness` expone `actions, runner, picker, renderPage, PAGES, OBSERVACIONES, pageDigest, formatDigest, observacionesPorBloques, observacionesDeIncidencia`.
- **Pantalla del panel**: `<section class="screen hidden" id="screen-x">` + `showScreen('screen-x')` + ids referenciados desde `panel.js`.
- **Skill que habla distinto en Jira**: en `skills.js`, `system(ctx)` ramifica por `ctx.product === 'jira'` a una función `xxxJira(ctx)` y deja `xxxConfluence()` con el texto de antes, byte a byte (los tests pinan `skillSystem(id, {product:'confluence'}) === skillSystem(id)`); lo que necesite del sitio (`projectKey`, `issueKey`) entra por `ctx` desde `baseSystem`, validado con regex antes de ir al prompt. Lo que cambie en la cabecera va en `productoBlock`/`navegacionBlock(skill, product)` de `prompts.js`, nunca en las reglas de seguridad.
- **Ajuste**: `DEFAULT_SETTINGS` + `migrateSettings` (config.js) + `applySettingsToUi` + `pushSettings` del SW si afecta al content script.
